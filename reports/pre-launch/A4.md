## 🔧 Fixes applied (review recommended)

**A4-2 — `astro` 7.0.3 → 7.1.6 (`package.json`, `package-lock.json`).**
`npm audit fix` alone cleared 4 of 6 findings (brace-expansion, js-yaml, postcss, svgo). The remaining two could not be fixed inside the pinned range. Re-auditing after that first pass surfaced what the original report had hidden behind the `sharp` entry: **astro `<=7.0.9` itself carried four high-severity XSS advisories** (GHSA-4g3v-8h47-v7g6 reflected XSS via View Transition animation properties; GHSA-f48w-9m4c-m7f5 XSS via unescaped spread attribute names; GHSA-7pw4-f3q4-r2p2 XSS via `transition:*` directive values; GHSA-8mv7-9c27-98vc `checkOrigin` bypass). Those are runtime XSS bugs in the shipped framework, not a build-time-only concern, so a pre-launch bump is warranted rather than an accepted risk. The bump also lifted the `sharp ^0.34.0` ceiling, letting `npm audit fix` take sharp to 0.35.3 and clear the libvips CVEs.

Kept the repo's exact-pin convention (`--save-exact`) rather than switching to a caret range. **Consequence: future astro patch-level CVEs will not apply automatically** — that pin needs a periodic manual review.

*Why this needs eyes:* it is a minor framework bump landed while another agent has uncommitted work in progress. `npm run build` succeeds — 73 pages, no errors, `check-fonts.js` clean — but nobody has visually diffed the rendered output between 7.0.3 and 7.1.6. Worth a quick look at a couple of pages.

**A4-5 — CSP scope narrowed (`public/_headers`).** Full before/after in the appendix. Also tightened `Permissions-Policy` `geolocation=(self "https://www.google.com")` → `geolocation=()`, since `www.google.com` was simultaneously dropped from `frame-src` and nothing in `src/` calls `navigator.geolocation`.

**A4-6 — documenting comment only** (`src/data/constants.ts:50–54`). No value changed.

*Explicitly not changed:* `X-XSS-Protection` remains absent (deprecated, deliberately removed previously — not reintroduced).

2. **A4-5 — confirm the tightened CSP live in B1.** Load a page with the Calendly embed and watch the console for `Refused to …` violations. Two residual uncertainties, both deliberate:
   - **`connect-src` has no Calendly origin.** Calendly's `widget.js` builds its URLs dynamically (grepping the shipped file for `https://` literals returns nothing), so I could not prove from source whether it makes parent-page XHRs. I left `connect-src` Calendly-free because the pre-existing CSP had no Calendly entry there either, and speculatively adding origins is exactly what this check exists to prevent. If B1 shows a `connect-src` violation, add `https://calendly.com https://assets.calendly.com`.
   - **`img-src` no longer contains the blanket `https:`.** Justified — zero remote images exist anywhere (verified against source markdown *and* the built HTML). But a future blog post embedding a remote image would now be silently blocked. Whoever owns the blog migration should know this. Revert for that case is to re-add `https:` to `img-src`.
3. **`form-action` is still unset — deliberately.** `default-src 'self'` does not cover `form-action`, so form-hijacking via injected markup is not blocked. I did **not** add `form-action 'self'`: `SITE_DATA.forms.careers` is currently `""` pending a third-party LeadFlow endpoint (`src/data/constants.ts:26–30`), and `form-action 'self'` would silently break that form the moment the endpoint is set. **Decide `form-action` at the same time the careers endpoint is chosen** — `'self'` if the handler stays same-origin, `'self' https://<handler>` otherwise.
4. **The astro exact pin** (see A4-2 above) needs a recurring manual update, since patch CVEs will not flow in automatically.

Runtime-only third parties, resolved from source rather than the build:
- **Calendly** — `src/components/CalendlyEmbed.astro` injects `https://assets.calendly.com/assets/external/widget.js` via IntersectionObserver (script-src), which loads `widget.css` (style-src) and appends an iframe on `calendly.com` (frame-src). `curl https://assets.calendly.com/assets/external/widget.css` → `url(/assets/external/close-icon.svg)`, a **root-relative** reference that resolves to `assets.calendly.com` — so that origin is a genuine `img-src` dependency. It was previously covered only incidentally by the blanket `https:`; now allowed explicitly.
- **gtag** — `src/layouts/BaseLayout.astro:106`, conditional on the (currently empty) GA ID.
- **ActiveCampaign** — `functions/api/subscribe.js:42` POSTs to `activehosted.com` **server-side from the Pages Function**, never from the browser. The file's own comment confirms this was a deliberate design choice to avoid opening the CSP. Correctly absent.
- **typeform / mykajabi / docs.google / gusto / irs.gov etc.** — plain `<a href>` navigations, not subresources. CSP `navigate-to` is not in use, so no directive applies.
