# Section B1 — Domain & Delivery 🌐

Phase B — requires the deployed staging/production URL. Read [PRE-LAUNCH-CHECKLIST.md](../../PRE-LAUNCH-CHECKLIST.md) execution rules first. Enumerate all item IDs; write your ledger to `reports/pre-launch/B1.md`. **Start by reading `reports/pre-launch/deferred.md`** — resolve any Phase A items that were blocked on deployment.

| ID | Action | Check | How to Verify | If Failed |
|----|--------|-------|---------------|-----------|
| B1-1 | 👁️ VERIFY ONLY | **DNS / domain resolves** | `dig <domain>` (or `nslookup`) resolves correctly; the site loads at the production domain in the browser. | Report DNS issues — registrar or hosting-level action required. |
| B1-2 | 👁️ VERIFY ONLY | **www ↔ apex canonical redirect** | Run `curl -sI https://www.<domain>/` and `curl -sI https://www.<domain>/<inner-page>/`. Both return **301** with a `location` pointing to the non-www equivalent (or the reverse, if www is primary — match the `site` value verified in A1). Path preserved, no redirect loop. Also `curl -sI` the primary version → **200**. | On **Cloudflare Pages**: domain → **Rules → Redirect Rules**; wildcard rule `https://www.<domain>/*` → `https://<domain>/${1}`, 301, preserve query string. Both apex and www must be added as custom domains and show "Active". Narrow overly broad patterns (`https://www.*`) to the specific domain to avoid 403s. On **Netlify**: `_redirects` rule `https://www.example.com/* https://example.com/:splat 301!`. On **Vercel**: project-settings redirect. |
| B1-3 | 👁️ VERIFY ONLY | **SSL & mixed content** | Load the site over `https://`; DevTools console shows zero mixed-content warnings on at least the homepage and one inner page. All external resources use `https://`. | Report offending `http://` URLs. Update references where possible; SSL provisioning itself is hosting-level. |
| B1-4 | 👁️ VERIFY ONLY | **Security headers served live** | `curl -sI https://<domain>/` — confirm every header from `public/_headers` is actually present in the response (X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Strict-Transport-Security, Permissions-Policy, Content-Security-Policy). Load the site with DevTools console open — zero CSP violation reports. | Headers missing live but present in `public/_headers` usually means a syntax issue (leading whitespace matters) or the file didn't deploy. CSP violations in console → the CSP scope audit (A4-5) missed an origin; fix `_headers` and redeploy. |
| B1-5 | 👁️ VERIFY ONLY | **Custom 404 served** | Browse to `https://<domain>/this-page-does-not-exist/` — the custom 404 page renders (not a hosting default) and the response status is 404 (`curl -sI`). | Cloudflare Pages serves `404.html` automatically in static mode. If a default page shows, check the build output contains `404.html` and `_redirects` has no catch-all overriding it. |
| B1-6 | 👁️ VERIFY ONLY | **Redirects behave** | For each rule in `public/_redirects`: `curl -sI https://<domain>/<source>` returns the configured status with the correct `location`, and the target returns 200 directly (no chained second redirect — targets must carry the trailing slash). | Fix `_redirects` targets (add trailing slashes) and redeploy. Missing legacy mappings require client input — ⏸ BLOCKED if the legacy URL list was never provided. |

> **🛑 CHECKPOINT:** Write the ledger, run the verification pass per the runbook before starting B2.
