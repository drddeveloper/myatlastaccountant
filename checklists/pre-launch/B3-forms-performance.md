Phase B — requires the deployed URL and a browser. Read [PRE-LAUNCH-CHECKLIST.md](../../PRE-LAUNCH-CHECKLIST.md) execution rules first. Enumerate all item IDs; write your ledger to `reports/pre-launch/B3.md`. This is the final section — after its verification pass, compile `reports/pre-launch/FINAL.md` per the runbook (a fresh context consumes all ledgers **and** `deferred.md`).

| ID | Action | Check | How to Verify | If Failed |
|----|--------|-------|---------------|-----------|
| B3-1 | 👁️ VERIFY ONLY | **Forms submit correctly** | Submit each form on the live site once. **Always fill the message/name field with a clear test marker — e.g. "TEST SUBMISSION — pre-launch check, please disregard" — these go to the client's real inbox/CRM.** Success state renders; error states render on invalid input (bad email, empty required fields). Confirm the notification arrived if inbox access exists. | Report which forms failed and the exact error. Backend config (email routing, CRM) is human action. Tell the human which test submissions to delete. |
| B3-2 | 🔧 FIX | **Form autocomplete attributes** | Inspect form fields on the live page: `autocomplete` set appropriately (`name`, `email`, `tel`, `street-address`, `address-level2`, `address-level1`, `postal-code`, `organization`). | Add missing attributes in the source per the [HTML autocomplete spec](https://developer.mozilla.org/en-US/docs/Web/HTML/Attributes/autocomplete); redeploy. |
| B3-3 | 👁️ VERIFY ONLY | **CTAs click through** | Click every call-to-action and external link on the live site. Destinations correct; `tel:`/`mailto:` open the right handlers (href values were preflight-verified in PF-16 — this is the behavioral check). | Report broken destinations with the page and link text. |
| B3-4 | 🔧⚠️ FIX WITH REVIEW | **Lighthouse targets** | Run Lighthouse (DevTools → Lighthouse, or `npx lighthouse <url>`) on the homepage and one inner page, mobile emulation. Targets: Performance ≥ 90, Accessibility ≥ 90, Best Practices ≥ 90, SEO ≥ 90. Paste all four scores per page as evidence. | Fix low-hanging items (unoptimized images → A3-2, render-blocking resources). Architectural issues (layout shift from design decisions, third-party weight) → flag for human review with the specific Lighthouse recommendation. |
| B3-5 | 👁️ VERIFY ONLY | **Responsive breakpoints** | View the live site at 375px, 768px, and 1440px widths. No layout breaks, overlapping text, horizontal scroll, or content hidden unintentionally. Check every page, not just the homepage. | Report issues with page + viewport + screenshot. Layout fixes may need design decisions — don't freelance visual changes. |
